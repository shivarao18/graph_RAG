Component Breakdown

  • User (Frontend): Submits a complex query (e.g., "Compare the revenue of companies facing supply chain risks").
  • LlamaIndex Orchestrator: Evaluates the semantic intent of the query and dynamically routes it to the optimal processing path. Can utilize a ReAct loop to decompose multi-part questions.
  • Path A (Qualitative): Enforces a strict ontology via the SchemaLLMPathExtractor to map unstructured documents into deterministic Nodes and Edges within Neo4j.
  • Path B (Quantitative): Uses a programmatic Semantic Layer (LlamaIndex NLSQLTableQueryEngine) to translate natural language into deterministic SQL, ensuring safe and accurate financial data retrieval from SQLite via read-only connections.
